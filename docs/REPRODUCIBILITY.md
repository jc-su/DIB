# Reproducibility Guide

This document tells a reviewer or external user exactly how to regenerate every
number, table, and figure that appears in the paper. The repository contains the
full DIB-Bench protocol, the controlled synthetic study, and two public-benchmark
anchors (GSM8K and BFCL-simple).

## 0. Environment

A 1x or 2x GPU with at least 24 GB of memory is recommended. The paper's
results were produced on 2x RTX A6000 (48 GB each). vLLM with FLASHINFER
attention is the fastest backend; the `transformers` engine is a
slower-but-simpler fallback for environments where vLLM kernels are
inconsistent.

```bash
conda create -n blind_eval python=3.10 -y
conda activate blind_eval
pip install -r requirements.txt
```

Versions used in the paper are recorded in every run's `run_metadata.json`
and inside the `runtime` block of every observed manifest.

## 1. Controlled Synthetic Suite (main study)

Reproduces the synthetic-suite block of Table 1 and Figure 3.

```bash
SEEDS="42 43 44" \
MODEL_SPECS=$'qwen14b|Qwen/Qwen2.5-14B-Instruct|Qwen/Qwen2.5-7B-Instruct|2|2048|32|0,1' \
bash run_paper_matrix.sh
```

For the smaller fast pair (single GPU):

```bash
SEEDS="42 43 44" \
MODEL_SPECS=$'qwen7b|Qwen/Qwen2.5-7B-Instruct|Qwen/Qwen2.5-1.5B-Instruct|1|2048|32|0' \
bash run_paper_matrix.sh
```

The cross-family Llama pair used in the aggregate:

```bash
SEEDS="42 43 44" \
MODEL_SPECS=$'llama8b_qwen7b|meta-llama/Llama-3.1-8B-Instruct|Qwen/Qwen2.5-7B-Instruct|1|2048|32|0' \
bash run_paper_matrix.sh
```

Outputs land under `paper_runs/<run_id>/`. Aggregate them into the package the
paper consumes:

```bash
python integrity_blindness.py aggregate \
  --inputs paper_runs \
  --out_dir paper_runs/aggregate \
  --include_run_id_regex "_vllm_seed[0-9]+$"
```

The aggregate directory then contains: `aggregate_condition.csv` (Table 1
source), `aggregate_model_pair_condition.csv` (Appendix C heatmap source),
`aggregate_component_ablation_matrix.tex` (Appendix D), `paper_table_*.tex`
(the body tables), and `paper_fig_*.pdf` (legacy bar/heatmap figures, kept for
the model-pair appendix).

## 2. GSM8K Anchor (Section 4, Table 1)

```bash
python scripts/make_gsm8k_anchor.py --n 50 --seed 42 \
  --out paper_runs/gsm8k_anchor/tasks.jsonl

BASE_MODEL=Qwen/Qwen2.5-7B-Instruct \
SUB_MODEL=Qwen/Qwen2.5-1.5B-Instruct \
ENGINE=vllm ATTENTION_BACKEND=FLASHINFER TP=1 N=50 SEED=42 \
CUDA_VISIBLE_DEVICES=0 GPU_UTIL=0.85 MAX_MODEL_LEN=2048 BATCH_SIZE=32 \
TASKS_FILE=paper_runs/gsm8k_anchor/tasks.jsonl \
OUTPUT_DIR=paper_runs/gsm8k_anchor/outputs \
RESULTS_DIR=paper_runs/gsm8k_anchor/results \
RUN_ID=gsm8k_anchor \
bash run_all.sh
```

Wall-clock: about 15 minutes on a single A6000 (model loads dominate).

(`gorilla-llm/Berkeley-Function-Calling-Leaderboard`, file
`BFCL_v3_simple.json`).

## 4. Paper Figures and Consolidated Table

After steps 1-3, regenerate the empirical result figure and the consolidated
three-benchmark table:

```bash
python scripts/make_paper_figures.py \
  --out_dir paper/figures --repo_root .

python scripts/make_consolidated_table.py \
  --out_tex paper/figures/table_consolidated.tex \
  --out_md paper/figures/table_consolidated.md
```

This produces `paper/figures/fig1_orthogonality.{pdf,png}`,
`fig2_stack.{pdf,png}`, and `fig3_results.{pdf,png}`. The paper imports
`fig3_results.pdf`; Figures 1 and 2 are drawn inline in
`paper/emnlp_deployment_integrity_blindness.tex`, with the generated copies kept
as companion exports for inspection. The scripts read
`paper_runs/aggregate/aggregate_condition.csv` and
`paper_runs/{gsm8k_anchor,bfcl_anchor}/results/summary.csv`.

## 7. Tamper Definitions

Each DIB tamper is defined in `integrity_blindness.py:observed_components`
(around lines 251-303). The clean baseline components are in
`clean_components` (around lines 201-248). Reading these two functions
together gives the exact textual content of every tamper used in the paper.
Specifically:

- `CLEAN_SYSTEM_PROMPT` (line 70) and `PROMPT_TAMPER_SUFFIX` (line 79)
- `CLEAN_TOOL_SPEC` (line 87) and `TOOL_TAMPER_SPEC` (line 98)
- `CLEAN_RETRIEVAL_POLICY` (line 109) and `RETRIEVAL_TAMPER_TEXT` (line 114)
- `CLEAN_DEPENDENCIES` (line 123) and `DEPENDENCY_TAMPER` (line 124)
- `apply_postprocess_tamper` (line 537)

## 8. Identity Channel

The identity evaluator is `integrity_blindness.py:integrity_evidence`
(around line 306). The canonical-JSON hash for each component is
`integrity_blindness.py:component_hash` (around line 135). The schemas the
released artifact validates against are at
`paper_runs/aggregate/{deployment_manifest,integrity_evidence,scored_example}.schema.json`.
